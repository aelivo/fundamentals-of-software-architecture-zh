## 哪些内容译得不好，怎样优化

| 位置 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- |
| CH04-002 | 软件必须完成……的所有事情 | 软件必须做到……的各个方面 | 架构特性不只是待完成的任务。用“做到／方面”表达软件必须具备的表现，保留与领域功能的区别。 |
| CH04-003 | 带有自我贬低的意味；团队如何能被说服，认真关注…… | 这个说法会贬低这些需求的重要性；既然叫……又如何说服团队给予足够重视 | self-denigrating 在此针对术语对这些需求重要性的削弱，原译生硬。保留作者个人偏好及反问语气。 |
| CH04-003 后译注 | 只直译 nonfunctional，缺少作者反感这个词的语境 | 简短说明英语 nonfunctional 也可表示“无法正常工作的” | 中文“非功能性”不自然带出这一负面词义。把说明明确标为译注，避免将作者对英文称呼的看法改成架构原则。 |
| CH04-004 | 架构特性符合三个标准 | 一项特性要成为架构特性，必须同时满足三个标准 | 明确三个条件的并列必需关系；属于清晰度改进，不将原译判成完全相反的意思。 |
| CH04-005、相应小标题、图 4-2 标签 | 指明一个非领域的设计关注点 | 指明领域之外的设计关注点 | 改善中文表达，不改变 nondomain 的边界；列表、说明标题、图中文字对照同步修改。 |
| CH04-008 | 规定成功的运维与设计标准 | 规定应用在运行和设计方面达到何种标准才算成功 | 原译“成功的标准”搭配含糊，并易把 operational 仅理解成运维工作；此处谈应用运行和设计的成功标准。分类名“运维架构特性”仍按术语表保留。 |
| CH04-009 | 需要专门设计某些东西 | 安全要求促使架构师作出专门的设计安排 | 把含糊的“东西”换成前后文已经明确的设计安排，保留结构影响这一判别条件。 |
| CH04-013 | 选择尽可能少、而非尽可能多的架构特性 | 尽可能精简所选择的架构特性，而不是追求数量最多 | 调整语序，保留作者对设计复杂性与数量取舍的强调，没有补充新的选择规则。 |
| CH04-021 | 例如良好的模块化……以及许多其他内部质量评估 | 例如确保模块化良好……并评估其他许多内部质量问题 | 原句把质量状态与评估活动并列，衔接不顺。改为责任所包含的动作，并明确共同承担是与他人共同承担。 |
| CH04-022 | 插入新功能；安装……的容易程度 | 增加新功能；安装……的难易程度 | 去掉英语式动作搭配，表格仍保留原来的问题形式与限定平台范围。 |
| CH04-026 | 一项坚定的要求 | 一项硬性要求 | firm requirement 是必须遵守的要求，“坚定”更常形容人的立场或意志。 |
| CH04-031 | 在交换信息，或者共享环境时，执行所需功能的程度 | 分别列出交换信息的能力，以及／或者在共享环境时执行功能的能力 | 原译改变了语法范围：把“交换信息”也写成执行功能的条件。恢复 can exchange… and/or perform… while sharing… 的结构，保留两种能力可兼有。 |
| CH04-035 | 独立组件 | 彼此分立的组件 | discrete 不直接表示组件之间没有依赖，更不表示可独立部署。避免给模块化定义加上原文没有的保证；本段另将“环境与需求”调整为“环境或需求”，保留两者均可能触发变更的意思。 |
| CH04-036 | 开发者将……迁移到……的程度；运行及使用环境 | 衡量开发者能在多大程度上将……迁移到……；运行或使用环境 | 原译“迁移的程度”不自然；在总定义和适应性子定义中均恢复 operational or usage 的选择关系，保留迁移环境的全部范围。 |

| CH04-048 | 让架构尽可能支持迭代 | 使其便于迭代 | as iterative as possible 在这里强调架构本身便于持续修改，原译容易像是在说支持某种开发流程；后文修改架构的解释完整保留。 |

## 原文问题与审校边界

- UDP 与 TCP 层次关系的原文疑点及已有译注保留。本轮不把原书表述升级成已验证的网络协议说明。
- 性能效率中的 capacity，原书确实写作超过既定上限的程度。本轮保留该措辞，并在笔记提醒不能将此转述直接当作标准的现行定义。
- ISO 段落按本书转述校译，未比对最新标准；术语、类别及举例不能据此视为当前版本的完整标准。
- 法规名称仅是表格举例，没有提供法律合规意见；安全／性能的相互影响按作者原有语气保留，不据此作产品性能保证。
- 支付段落的 these two criteria 所指不够明确，译文保留“这两个判断条件”，没有自行改成“两种支付情境”或指定只指三个条件中的哪两个。
- 本轮完成逐段校译；独立复审仍待进行，其余章节的进度另见总表。
